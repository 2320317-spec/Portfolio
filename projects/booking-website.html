01

Situation

A real client, a real problem

A school project with a twist: it required a real client. We partnered with the host of a staycation unit who had strong branding but no website of her own — and a recurring double-booking problem that hurt both the host and her guests. Bookings lived in chat threads and calendars that didn't talk to each other.

02

Task

Backend developer on a student team

We built it as a team, and I owned the backend: the MySQL database design and the PHP logic behind it — most importantly, the booking engine itself, where the double-booking problem had to be solved at the data level, not patched over in the interface.

03

Action

How I built it

The front end is HTML, CSS, and JavaScript; the backend is PHP on a MySQL database. The heart of my work is the availability check: a booking is only accepted if no confirmed reservation overlaps the requested dates — the kind of guarantee that has to live in the database query itself. 

-- The double-booking guard: two date ranges overlap when
-- each one starts before the other one ends.
SELECT COUNT(*) FROM bookings
WHERE status = 'confirmed'
  AND check_in  < :requested_check_out
  AND check_out > :requested_check_in;
-- 0 rows -> the unit is free, booking proceeds
04

Result

What it achieved

The site is in active development — we're finishing it to be fully functional and error-free before it goes live for real guests. It has also been my proving ground: the project where classroom concepts became a working full-stack system with a client on the other end.
