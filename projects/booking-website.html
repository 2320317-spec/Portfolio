01

Situation

Working with a real client

This started as a school project that required us to find an actual client. We ended up working with the host of a staycation unit called Amari. She already had good branding, but no website of her own, and she kept running into double bookings because reservations were scattered across chats and separate calendars. That was the problem we wanted to solve for her.

02

Task

My part: the backend

We worked on this as a team, and I took the backend side, designing the MySQL database and writing the PHP behind it. The part I spent the most time on was the booking logic, since that's where the double-booking issue actually had to be handled.

03

Action

How we built it

The front end is plain HTML, CSS, and JavaScript, and the backend runs on PHP with a MySQL database. The main thing I had to get right was the availability check. Instead of trying to catch conflicts in the interface, I made the database answer the question directly: a booking only goes through if no confirmed reservation overlaps the dates being requested.

Calendar integration:
  • Flatpickr library (CDN: https://cdn.jsdelivr.net/npm/flatpickr)
  • Branded date picker with custom colors
  • Min date validation (can't book in the past)
  • Checkout date must be after check-in
-- The double-booking guard: two date ranges overlap when
-- each one starts before the other one ends.
SELECT COUNT(*) FROM bookings
WHERE status = 'confirmed'
  AND check_in  < :requested_check_out
  AND check_out > :requested_check_in;
-- 0 rows -> the unit is free, booking proceeds
04

Result

Where it stands

The site is still in development. We're working through the remaining features and fixing what breaks before it goes live for real guests. Looking back, this is the project that taught me the most — it was the first time the things I learned in class had to hold up for someone outside of school.
