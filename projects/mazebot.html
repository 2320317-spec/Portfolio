01

Situation

A maze and a robot

A school project, and honestly the one I had the most fun with. The goal was simple to say and harder to do: build a small robot that can find its own way through a maze, with no one steering it. Four of us worked on it together.

02

Task

Mostly the hardware side

We started building it together as a group of four. As it went on I ended up focusing on the hardware — wiring the sensors and motors, putting the chassis together, and keeping the electronics working through testing — plus some of the code that runs on it.

03

Action

From random turns to one rule

An Arduino Uno reads the sensors and drives the servos. Ultrasonic sensors measure how far the walls are, IR sensors pick up what's close on the sides, and the whole thing runs off a battery pack so it isn't tied to anything.

On our first trial the robot basically moved at random — whenever it saw no obstacle, it just went that way. It did eventually stumble forward, but it wandered, repeated paths, and there was no way to predict it. So we stopped and actually looked at the maze, traced the shortest way through, and realised we didn't need the robot to be clever at all. We rewrote it to follow only the left wall. One rule, and it made it through consistently.

Hardware used

How it solves the maze

  1. Check the left side first — if there's an opening there, turn left and take it.
  2. If the left is walled, keep going straight for as long as the path ahead is clear.
  3. If both the left and the front are blocked, turn right and start over from step one.
// Left-wall following: always prefer the leftmost opening.
// Keeping one hand on the same wall walks you through the
// whole maze — the robot needs no map and no memory.
if (leftIsOpen()) {
    turnLeft();
    forward();
} else if (frontIsOpen()) {
    forward();
} else {
    turnRight();   // walled on the left and ahead
}
04

Result

It solved the maze

MazeBot passed — it gets through the maze on its own. What stuck with me wasn't the robot itself but how we got there: our first instinct was to let it figure things out as it went, and that turned out to be the harder and worse way. Studying the maze first and picking a rule that fit it beat trying to be clever, and it's something I've caught myself applying to code since.
